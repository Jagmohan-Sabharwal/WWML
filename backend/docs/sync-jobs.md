# Synchronization jobs

Revision `0005_sync_jobs` adds the requested `sync_jobs` table and SQLAlchemy
`SyncJob` model. This change defines persistence only: it does not modify the
watcher, create jobs automatically, add API endpoints or start synchronization.

| Column | Type | Default / meaning |
| --- | --- | --- |
| id | UUID primary key | Application-generated UUID |
| status | varchar(32) | pending |
| started_at | timestamp with timezone, nullable | Set when a job starts |
| completed_at | timestamp with timezone, nullable | Set when a job terminates |
| files_scanned | bigint, non-null | 0; files observed in the run |
| files_imported | bigint, non-null | 0; successfully imported files |
| files_skipped | bigint, non-null | 0; files deliberately not imported |
| errors | JSONB array, non-null | []; safe structured error summaries |

Statuses are `pending`, `running`, `completed`,
`completed_with_errors`, and `failed`. Pending jobs have no timestamps; running
jobs require started_at and have no completed_at. Terminal states require both
timestamps, with completed_at greater than or equal to started_at.

Database constraints reject unknown states, negative counters, imported plus
skipped counts exceeding scanned, inconsistent timestamps and a non-array errors
value. Failed or unfinished files may account for the difference between scanned
and imported plus skipped. Error-array length is not a failed-file count: a run
may have errors unrelated to individual files.

Counters, status and errors have database defaults as well as ORM defaults.
UUIDs are generated by SQLAlchemy; raw SQL inserts must supply an ID.
A started_at/id index supports ordered history reads.

An error summary can be `{"code":"download_unavailable","file_id":"source-id"}`.
Future writers must sanitize errors before persisting them: never include access
tokens, credentials, response bodies or raw exception traces. Array appends are
tracked by SQLAlchemy's MutableList; replace entries or the list when editing
nested error objects.

Apply with `docker compose exec -T backend alembic upgrade head` after building
the updated backend. `alembic downgrade 0004_asset_soft_delete` removes sync job
history while preserving Assets and existing per-file records. Back up run
history before a production downgrade.

Unit tests cover metadata registration and offline migration SQL. PostgreSQL
tests verify defaults, lifecycle states, counter constraints, mutable error
persistence, timezone-aware timestamps and migration round trips.
